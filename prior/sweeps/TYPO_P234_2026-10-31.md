# The single edit at paragraph 234: what it is, what it is not, and a correction

## 1. What the delta is

Hal's post, paragraph H5, spells `facinating`. So does **her own certified stage-one answer**
(`preimages/r2b77_stage1.txt`, md5 `9dd2efb9…` -> `19TbyN5…`): the word sits at byte 1,286 in both,
identical offset, unchanged. The chapter at paragraph 234 spells `fascinating`. One letter inserted
('s', after `fac`), which is the only difference anywhere in the 316-token / 1,289-letter quotation.

## 2. Why this is a spell correction and not a planted marker

1. **She did not touch it in stage one.** Her certified first-stage text preserves the typo at the
   same byte. If the misspelling were a signal, it would have mattered there first.
2. **The fix therefore marks a provenance split.** The stage-two question text was assembled from a
   copy of the post that had already been spell-checked, not from her stage-one working file. That is
   the edit's real content: the two working files are not the same file.
3. **It removes an anomaly rather than adding one.** Every genuine planted oddity in the chapter is
   visible as oddity (`ppM` at 73, the alphabet address at 126, `VIrgin` at 128, `BItcoin` at 136).
   This change makes the text more orthographically normal, which is the opposite of how a marker has
   to behave if the solver is meant to find it.

## 4. Positional arithmetic (byte-exact, CRLF base, 46,000 bytes, 35,825 letters)

| quantity | value |
|---|---|
| `fascinating` starts at | byte 40,031 = global letter 31,191 |
| the inserted letter is | byte 40,034 = global letter 31,194 (≡ 42 mod 44) |
| paragraph 234 | bytes 39,673-40,043, 301 letters, 63 words |
| the edited word is | **word 63 of 63, the paragraph's last word** |
| paragraph-final letter | `g`, unchanged by the edit |

The edit is inside the paragraph's final word, so it is the one position class the stage-one rule
actually uses. But it does not change that letter: it changes the length by one. Its only mechanical
effect is to shift every downstream letter index by +1 relative to a typo-free copy.

Consequence for the repo: **any positional family must be evaluated in both alignments** (counting
the inserted letter or not) for everything after global letter 31,191. That is a 2x factor on
positional families, not a new family. Stride families are unaffected as families: letter-granularity
strides 4, 7, 11, 22 and 44 with every offset and four directions were closed in
`SESSION_2026-10-30_second.md`, and word-granularity strides for all ten stride keys in
`sweeps/stride_case_selectors.py`.

## 5. CORRECTION: the previous turn's edge sweep was byte-misaligned

The chapter contains **six U+00A0 characters**, at character positions 9,084, 16,922, 17,272,
17,780, 33,411 and 43,301. String length is 45,994; encoded length is 46,000. The previous turn's
edge-intersection sweep (972 derivations) and its Finney-block supplement (222) computed flip
positions on the decoded string and applied them to a bytearray of the encoded text, so every
position past character 9,084 was off by one to six bytes. **Those 1,194 derivations hashed the wrong
letters and are void, not merely negative.**

Re-run byte-exact as `sweeps/edge_intersection_byte.py`: 12 sets (the enumerator initials, the
capital sentence-closers, the all-caps subset, the union pool, all three complements, the two
enumerations, finney4, finney5, finney5+222), 8 mode directions, 14 singleton paragraphs, both
certified bases, indices 0/1/2/76/77. **1,770 derivations, zero hits.** The conclusion survives; the
count from that turn does not.

Unaffected by the bug: `sweeps/letter_class.py` (built and indexed in byte space throughout), the
demo work (`demo_base.txt` is pure ASCII, 1,549 chars = 1,549 bytes), and `sweeps/typo_marker.py`'s
restore-only candidates (no positional edits).

**Repo-wide audit item:** any script that computes positions from the decoded paragraph strings and
hashes `text.encode()` is suspect for the same reason. The six NBSP offsets above are the only
divergences, so the damage is confined to positions after 9,084 and grows by one byte per NBSP.
