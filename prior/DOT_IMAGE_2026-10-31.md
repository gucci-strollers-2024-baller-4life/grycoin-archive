# The dots image: it is the genesis address, and what that does and does not give

**Date:** 2026-10-31
**Source:** `assets/dots_tweet_1153435788626948097.jpg`, downloaded from
`https://pbs.twimg.com/media/EAHTuzvVUAE-Oh0.jpg` (1191 × 99 px), the single media item on
@NakamotoAoi's account.
**Tooling:** OCR via `rapidocr-onnxruntime`, 3× upscale, inverted. Confidence 0.98.

## 1. What the image says

```
1A1zP1eP5QGefi2DMPTfTL5SLmv7DivfNa.
```

The genesis coinbase address **with a trailing period**, set in a dotted display face. The trailing
period is not OCR noise: it makes the line byte-identical to **¶1 of Wattpad part 761570746**,
"The Satoshi Code", which is exactly the part the tweet links to:

> "@NakamotoAoi, 22 Jul 2019: Moved the solution to the genesis block puzzle to a new part of the
> Wattpad story — wattpad.com/761570746-second-the-satoshi-code"

So the image is a preview of that part's first line, rendered as an image so the address cannot be
found by searching the post's text.

## 3. The published oracles reproduce

Both partial hashes check out against the natural plaintexts, locally:

```
md5("Hal Finney")        = cc9485a…    ¶145, "the two plaintext items read from the left"
md5("ihsotaS otomakaN")  = d78c92f…    ¶146, the same pair read from the right
```

`d78c92f` matching `ihsotaS otomakaN` is what `INHERITANCE_KEY_2026-10-31.md` already records;
`ORACLE_CALIBRATION_2026-10-31.md` still lists it as unexplained after ~590,000 candidates and is
stale on that line. The assembled string is `preimages/r1b77.txt`, md5 `684b250e…`, deriving
`1FAAKpzFc2CGU6Yt51kAZv5f6dXZckRsMP`, which `BLOCK77_KEYS.md` already carries as verified.

So the image does not *recover* round one; round one is recovered, and the image is the piece of
ephemera that ties the published address to the part that explains it.

## 4. The image is not the stage-two preimage

Nineteen candidate preimages were run through the certified lane
(MD5 → 16-byte BIP39 entropy → seed → m/44'/0'/0'/0/0 → P2PKH) and screened against all four
escrows, including `14zMkTgaVXJcxdh4JdWi29MLRR44iUSG9W`:

| candidate family | examples |
|---|---|
| the address as text | bare, lowercase, uppercase, reversed, no leading `1`, no trailing `a` |
| with punctuation | `+ "."`, `+ "\n"`, `+ ".\n"` |
| the author's own renderings | `1A1zP1eP5QGefi2DMPTfTL5SLmv 7 DivfNa`, with and without the period |
| the genesis public key | ¶89's 130-hex value, upper, lower, with period |
| assembled forms | the two halves joined, the three-part split |

**Zero hits.** The address is not the stage-two preimage in any reading of it I can justify.

## 5. What the image does give

The author's reply on the stage-one thread says the route is "impossible to write a script" and that
"there is a hint on how to solve this right in the post by Hal", "much like the Aa in the genesis
block address". Combined with ¶110 and ¶114, that is a description of a device with two properties:

1. **An edge pair is the instruction.** The first character and the last character of the object
   tell you how to read it. `Aa` says Atbash; the four window paragraphs' first and last letters are
   the same kind of pointer, and the transport rule is the same geometry.
2. **Two halves, one ciphertext item each.** ¶114 splits the object at its central letter and ¶138
   puts one item in each half. The object is not read as a whole; it is read as two mirrored halves.

Property 2 is the one the chapter work has not tried. Every sweep so far treats the chapter as one
273-paragraph object with a single four-unit selection. The address device is a *bipartite* reading:
split, then one item per half. For the chapter the split points that exist are the three act
markers, the mid-paragraph at ¶137, and the four window starts.

## 6. The two-halves reading, run

`sweeps/half_split.py`. For each split point the chapter is cut, and one marked unit is taken from
each side, then carried through the certified lane.

| pool | splits | sets | derivations | hits |
|---|---|---|---|---|
| live uses ({20, 42, 220, 273}) | ¶88, ¶137, ¶163, ¶5, ¶93, ¶168, ¶231 | 23 | 828 | 0 |
| every sign-sentence paragraph (18) | ¶88, ¶137, ¶163, ¶231 | 139 | 5,004 | 0 |
| | | **162** | **5,832** | **0** |

Under a second, in 0.86 s of local compute, no credits. So the bipartite shape taken literally from
¶114 and ¶138 is negative on this vocabulary. What it does not rule out is the split point being
chosen by something other than a structural marker, and the two halves carrying units that are not
drawn from the sign vocabulary at all.

## 7. Where that leaves the image

The image is ephemera, and it is now identified, saved and committed: it points at the part that
explains round one, and round one is already recovered and independently corroborated by the two
published partial hashes. It does not contain the stage-two preimage, in any of nineteen readings
tested, and the device it advertises, applied literally, is negative on the chapter's sign
vocabulary.

The one thing it changes is the shape of the problem. The chapter's answer may not be a single
four-unit selection at all, but two items, one per half, assembled the way `Hal Finney` and
`ihsotaS otomakaN` are assembled into a 112-character submission.
